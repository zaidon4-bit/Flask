# Infinite Academy — Flask + Supabase + VdoCipher

> **الانتقال من localhost إلى موقع عام:** راجع [دليل التشغيل العام بدون localhost](NO_LOCALHOST_PUBLIC_SETUP_AR.md). عنوان `127.0.0.1` مخصص للتجربة على جهازك؛ النسخة العامة يمكن نشرها على Render عبر HTTPS (ملف `render.yaml` جاهز)، والـAPK يُبنى على رابط الموقع العام عبر `ACADEMY_BASE_URL`.
> **تريد APK من الهاتف؟** اتبع [دليل البداية السريع لبناء APK عبر الإنترنت](BUILD_APK_ONLINE_START_HERE_AR.md). التوصية المجانية للتجربة: Render للموقع + Supabase لقاعدة البيانات + GitHub Actions لبناء التطبيق الأصلي.
> **النشر المجاني المقترح:** اتبع [دليل Render + Supabase + GitHub Actions](RENDER_SUPABASE_GITHUB_ACTIONS_SETUP_AR.md).


نسخة تجريبية لمنصة دورات عربية قابلة للنشر من GitHub على Render أو Railway. تشمل تسجيل الطلاب مع رقم واتساب، تفعيلاً وإلغاء تفعيل يدويين بلا أكواد ولا اشتراك شهري، لوحة إدارة، إدارة الأجهزة، إنشاء الدورات والدروس، وسجل أحداث أمني. مشغّل الفيديو يتصل بـ VdoCipher من جهة الخادم.

## 1) ماذا يوجد في المشروع؟

- واجهة عربية RTL ومتجاوبة للهاتف.
- تسجيل وإنشاء حساب بكلمات مرور مجزّأة (hashed)، وليس نصاً مكشوفاً.
- كل حساب طالب جديد يبدأ بحالة `pending` ويضيف الاسم والبريد ورقم واتساب وكلمة المرور؛ لا يتم إرسال روابط عبر البريد ولا توجد مصادقة بريدية. المدير وحده يفعّل الحساب أو يلغي تفعيله. لا توجد أكواد تفعيل أو مدد اشتراك أو تواريخ انتهاء.
- لوحة إدارة تعرض رقم واتساب كرابط للمراسلة، وتسمح بتفعيل/إلغاء تفعيل الحساب، ومراجعة الأجهزة واعتمادها أو حظرها أو فك ارتباطها.
- متصفح الويب يستخدم رمزاً عشوائياً في Cookie من نوع `HttpOnly` وتُخزّن بصمته فقط. مسار APK الأصلي يستخدم UUID لتثبيت التطبيق ومفتاح EC P-256 في Android Keystore، ثم يثبت امتلاك المفتاح بتوقيع challenge عشوائي لمرة واحدة يصدره الخادم. يخزّن الخادم تجزئة المعرّف والمفتاح العام فقط؛ المفتاح الخاص لا يغادر Android Keystore. يبقى اعتماد الجهاز قراراً مستقلاً للأدمن.
- إنشاء الدورات والدروس من لوحة الإدارة وإدخال VdoCipher Video ID.
- فحص حالة قواعد البيانات عبر `/health`.
- يدعم حتى 3 أدوار قواعد بيانات منفصلة في البداية: رئيسية للحسابات والأجهزة، محتوى للدورات والدروس، وتدقيق للأحداث الأمنية. يمكن استخدام مشروع Supabase واحد أو عدة مشاريع. لا توجد علاقات SQL بين قواعد مختلفة؛ تُحفظ معرفات الربط كقيم عادية عندما تعبر القواعد.

> تنبيه: اكتشاف الجهاز في الويب ليس إثباتاً لهوية قطعة العتاد. حذف Cookies أو تغيير المتصفح قد يظهر جهازاً جديداً. كذلك، لا توجد حماية فيديو تمنع كل وسائل تصوير الشاشة.

## 2) تشغيل محلي للتجربة

تحتاج Python 3.11 أو أحدث.

```bash
cd infinite-academy-supabase
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-local.txt
cp .env.example .env
```

افتح `.env` وعدّل `SECRET_KEY` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` إلى قيم حقيقية. لا تترك كلمات المرور الافتراضية أو الأمثلة؛ على Render وRailway يمنع التطبيق الإقلاع إذا بقي `SECRET_KEY` على قيمة المثال. اترك روابط قواعد البيانات فارغة مؤقتاً لتجربة محلية على SQLite، أو أضف رابط Supabase إلى `DATABASE_URL_MAIN`. استخدم `requirements-local.txt` للتجربة المحلية و`requirements.txt` للنشر الذي يحتاج اتصال Postgres. شغّل:

```bash
python app.py
```

افتح `http://127.0.0.1:5000`. الدخول الإداري يكون بالبريد وكلمة المرور من `.env` إذا لم يكن البريد مستخدماً مسبقاً. إعادة تعيين كلمة مرور الطالب تتم من لوحة الأدمن فقط، ولا تُرسل أي كلمة مرور عبر البريد. لا تستخدم كلمة مرور حقيقية مشتركة مع حسابات أخرى.

بعد تثبيت المتطلبات، شغّل اختبارات مسارات الحسابات والأجهزة على قاعدة SQLite مؤقتة (لا تستخدم قاعدة بيانات الإنتاج):

```bash
python -m unittest discover -s tests -v
```

الاختبارات لا تشغّل VdoCipher الفعلي؛ يلزم اختبار تشغيل الفيديو يدوياً بعد ضبط الخدمة.

### ملاحظات مهمة لحساب المدير الأول

- إذا كان `ADMIN_EMAIL` و`ADMIN_PASSWORD` قيمتين حقيقيتين (ليس بريد المثال أو نص `replace-with`، وكلمة المرور بين 12 و128 محرفاً) ولم يوجد البريد مسبقاً، يُنشأ مدير أول مرة عند بدء التطبيق.
- تغيير `ADMIN_PASSWORD` لاحقاً لا يعيد تعيين كلمة مرور حساب موجود. لإعادة تعيين كلمة مرور طالب، استخدم النموذج الموجود في صف الطالب داخل لوحة الأدمن؛ لا توجد استعادة بالبريد.
- لا تضع ملف `.env` في GitHub. يتجاهله `.gitignore`، واحتفظ بـ `.env.example` فقط.

## معرّف التثبيت لتطبيق APK مستقبلاً

يحتوي `android-app/` على مشروع Android أصلي يستخدم `WebViewCompat.addWebMessageListener` مع allowlist لأصل HTTPS واحد، ويولّد مفتاح توقيع في Android Keystore. يعتمد تسجيل الدخول الأصلي على `/api/device/challenge` والتحقق الخادمي من توقيع ECDSA لمرة واحدة. لا يكفي محوّل URL-only؛ يجب بناء APK من مشروع Android ودعم الجسر الأصلي. ترحيل قاعدة البيانات إضافي ويحافظ على سجلات الأجهزة. سجلات v9 التي تفتقد المفتاح تحتاج موافقة أدمن مرة واحدة عند ربط المفتاح.

## 3) ربط Supabase — قاعدة واحدة أو عدة قواعد

من لوحة Supabase، افتح المشروع ثم **Connect** وانسخ Connection string المطابقة لطريقة اتصال الخادم. على الاستضافات التي لا تدعم IPv6، غالباً تحتاج إلى **Session Pooler**؛ استخدم المضيف والمنفذ واسم المستخدم كما تعرضها Supabase حرفياً. أضف `sslmode=require` إذا لم تكن موجودة، وبدّل placeholder كلمة المرور بكلمة مرور قاعدة البيانات. إذا احتوت كلمة المرور على رموز خاصة، يجب أن تكون URL-encoded.

أضف هذه المتغيرات في `.env` محلياً أو صفحة Environment في Render / Variables في Railway:

```env
DATABASE_URL_MAIN=postgresql://.../postgres?sslmode=require
DATABASE_URL_COURSES=postgresql://.../postgres?sslmode=require
DATABASE_URL_AUDIT=postgresql://.../postgres?sslmode=require
```

الأدوار:

| المتغير | ما يُخزّن فيه | إلزامي؟ |
|---|---|---|
| `DATABASE_URL_MAIN` | المستخدمون، حالة التفعيل، رقم واتساب، الأجهزة | نعم عند استخدام Supabase |
| `DATABASE_URL_COURSES` | الدورات والدروس ومعرّفات فيديو VdoCipher | لا؛ عند تركه فارغاً يستخدم القاعدة الرئيسية |
| `DATABASE_URL_AUDIT` | أحداث الدخول، الأجهزة الجديدة، إجراءات المدير | لا؛ عند تركه فارغاً يستخدم القاعدة الرئيسية |

كل URL مستقل إذا كان يتجه إلى مشروع/قاعدة مختلفة. وضع رابطين مختلفين لنفس مشروع Supabase لا ينشئ قاعدة جديدة تلقائياً؛ تأكد من المشاريع التي نسخت منها الروابط. إذا أردت بساطة التجربة أولاً، استخدم `DATABASE_URL_MAIN` فقط واترك الرابطين الاختياريين فارغين. عند التشغيل الأول، ينشئ التطبيق الجداول التي يحتاجها إن لم تكن موجودة.

**لا تُرسل كلمات مرور قواعد البيانات أو روابط الاتصال الكاملة في الدردشة أو ترفعها إلى GitHub.** إذا سبق أن نشرت رابطاً يحتوي على كلمة مرور، أعد تعيين كلمة مرور قاعدة البيانات.

## 4) النشر المجاني على Render + Supabase

المسار الأساسي المجهّز في هذه النسخة هو Render للموقع + Supabase PostgreSQL + GitHub Actions لبناء APK. اتبع الخطوات التفصيلية في [`RENDER_SUPABASE_GITHUB_ACTIONS_SETUP_AR.md`](RENDER_SUPABASE_GITHUB_ACTIONS_SETUP_AR.md).

- ملف `render.yaml` يضبط أمر البناء والتشغيل وفحص `/health` وخيارات الإنتاج.
- التطبيق يتعرف على بيئة Render وRailway، ويشترط `DATABASE_URL_MAIN` و`SECRET_KEY` في الاستضافة، ويفرض الكوكيز الآمنة خلف HTTPS.
- Render يعطي نطاق `onrender.com` وشهادة HTTPS تلقائية. الخطة المجانية تنام بعد 15 دقيقة من الخمول؛ لذلك قد يتأخر أول فتح بعد النوم.
- استخدم Supabase Shared Pooler / Session mode كما يظهر في لوحة Connect، ولا تستخدم SQLite في الإنتاج.

## 5) إعداد VdoCipher

1. ارفع فيديو من لوحة VdoCipher واستخرج **Video ID**.
2. في إعدادات Environment لمزوّد الاستضافة أضف `VDOCIPHER_API_SECRET` بالمفتاح السري من لوحة VdoCipher. لا تضعه في HTML أو JavaScript أو مستودع GitHub.
3. من لوحة الإدارة أنشئ دورة ثم أضف درساً باستخدام Video ID.
4. سجّل الدخول بحساب طالب فعّله المدير وافتح الدرس. صفحة الدرس لا تحمل OTP داخل HTML؛ يطلب المتصفح بيانات التشغيل من `POST /lessons/<lesson_id>/playback`، والخادم يعيد فحص تفعيل الحساب واعتماد الجهاز وصلاحية الجلسة قبل أن يطلب OTP قصير العمر من VdoCipher.
5. لا تعتمد حماية الفيديو على إخفاء رابط الصفحة: مسارات الدورة والدرس وطلب التشغيل محمية على الخادم. طلب التشغيل لا يصدر بيانات تشغيل لجهاز غير معتمد أو حساب غير نشط، وتُمنع الاستجابات التي تحتوي بيانات الدرس من التخزين المؤقت.

إذا كان مفتاح VdoCipher غير موجود، ستظهر صفحة الفيديو في وضع التجربة مع رسالة إعداد بدلاً من أن يعمل الفيديو. راجع وثائق VdoCipher الحالية إذا اختلف مسار API أو متطلبات الحساب.

## 6) متغيرات البيئة

- `SECRET_KEY`: سر جلسات Flask، طويل وعشوائي وفريد.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD`: إنشاء حساب المدير الأول فقط إذا لم يوجد البريد.
- `SUPPORT_WHATSAPP_NUMBER`: رقم واتساب الدعم بالأرقام الدولية فقط دون `+` أو مسافات. يُستخدم في رسالة جاهزة تتضمن البريد المسجّل وطلب المساعدة؛ لا تُضمّن كلمات المرور أو رموز الجلسة في الرسالة.
- `DEVICE_LIMIT`: العدد الأقصى للأجهزة المعتمدة (افتراضياً `1`، والحد الأعلى المدعوم `5`). الجهاز الأول فقط يُعتمد تلقائياً؛ أي تثبيت جديد بعد وجود سجل سابق ينتظر الإدارة. عند اعتماد جهاز بديل، تُوقَف الأجهزة الأقدم بما يحافظ على الحد، وتُبطَل الجلسات السابقة.
- `SINGLE_SESSION=true`: كل دخول جديد لطالب يبطل الجلسة السابقة. هناك أيضاً `session_version` يُستخدم لإبطال الجلسات بعد إيقاف الحساب أو الجهاز أو تغيير كلمة المرور.
- يستطيع المستخدم المسجّل تغيير كلمة مروره بعد إدخال كلمة المرور الحالية. إذا نسيها، فلا توجد استعادة بالبريد؛ يعيد الأدمن تعيينها من لوحة الإدارة. تعيين كلمة مرور جديدة من الأدمن يبطل الجلسات السابقة.
- `whatsapp_number`: يُدخله الطالب عند التسجيل بصيغة دولية مع مفتاح الدولة. يظهر للمدير رابط مباشر لبدء محادثة WhatsApp.
- لا يوجد انتهاء تلقائي للحساب: يظل `active` حتى يضغط المدير «إلغاء تفعيل الحساب». عمود انتهاء الاشتراك من النسخ السابقة غير مستخدم؛ التحديث يضيف عمود واتساب إلى قاعدة موجودة دون حذف بياناتها.
- `COOKIE_SECURE`: اجعله `true` في بيئة HTTPS الفعلية. اتركه `false` فقط على localhost عبر HTTP.
- `VDOCIPHER_API_SECRET`: مفتاح واجهة API لفيديوهات VdoCipher، يبقى على الخادم.

## 7) قبل استقبال مدفوعات حقيقية

هذه **نسخة تطوير** وليست مراجعة أمنية مستقلة أو جاهزية إنتاج مثبتة. لا توجد استعادة كلمة مرور عبر البريد؛ إعادة التعيين اليدوية محصورة بلوحة الأدمن. قبل الإطلاق العام، لا يزال مطلوباً: migrations بإصدارات بدلاً من الاعتماد على `create_all` للتحديثات؛ سياسة نسخ احتياطي واختبار استعادة؛ اختبار CSRF والجلسات ومعدل المحاولات على بيئة حية؛ مراقبة التكلفة؛ وشروط خصوصية واضحة. سجلات الأحداث قد تحتوي على عنوان الاتصال وسلسلة المتصفح، فاحتفظ بها للمدة اللازمة فقط.

## الملفات

- `app.py` — التطبيق، النماذج، المصادقة، قواعد البيانات، VdoCipher API.
- `templates/` — الصفحات العربية.
- `static/style.css` — التصميم المتجاوب.

## Active-device status (new)

- The student browser sends a heartbeat on initial page load, every 30 seconds while the tab is visible, and when the tab becomes visible again.
- The admin dashboard marks an approved device as **active now** when its last heartbeat is within the previous 120 seconds.
- Older registered devices remain in the inventory but are marked inactive. The count measures recent browser activity, not a guaranteed physical-device identity or proof that a person is watching the screen.
- The startup migration adds `devices.last_active_at` to existing databases without deleting existing device rows.

## حماية ضد مشاركة الحساب (جديد)

- **معرّف الجهاز الأساسي:** رمز عشوائي محفوظ في Cookie من نوع `HttpOnly`؛ لا يُرسل الرمز الخام إلى قاعدة البيانات بل تحفظ بصمته SHA-256. داخل WebView يبقى هذا المعرّف عادةً ما دامت بيانات التطبيق محفوظة. حذف التطبيق أو بياناته قد ينشئ معرّفاً جديداً.
- **بصمة الشاشة وCanvas وWebGL:** تُحفظ كبصمة مساعدة للمراجعة فقط، ولا تُستخدم وحدها لإعادة اعتماد الجهاز تلقائياً؛ فقد تتغيّر في المتصفح نفسه أو تتشابه بين جهازين.
- **طلب جهاز جديد أو إعادة تثبيت:** الجهاز الأول فقط يُعتمد تلقائياً. الجهاز الجديد بعد وجود سجل سابق ينتظر مراجعة الإدارة، ولا يُعتمد بمجرد تشابه بصمته. تظهر بيانات الطالب ورقم واتساب المسجّل في لوحة الإدارة، ومنها يمكن بدء محادثة للتحقق يدوياً.
- **استبدال الجهاز:** عند موافقة الإدارة على جهاز بديل لطالب، يُعتمد الجهاز الجديد وتُحوّل الأجهزة السابقة المعتمدة إلى `blocked` مع الاحتفاظ بسجلاتها للمراجعة. تُبطل الجلسة القديمة ليُطلب من الطالب تسجيل الدخول من الجهاز الجديد. لا يؤدي الطلب وحده إلى إلغاء تفعيل حساب الطالب.
- **الأدمن:** يتجاوز فحص الأجهزة، ولا ينشئ هذا الفحص سجلاً مطلوب الموافقة له، حتى لا يتعطل دخوله بسبب تغيير المتصفح أو Cookie.
- **جلسة واحدة:** أي تسجيل دخول جديد يُنهي الجلسة القديمة للطالب (`SINGLE_SESSION=true`). وتسجيل الخروج يُنهي الجلسة ويجعل الجهاز غير نشط فوراً؛ أما إغلاق التبويب بدون خروج فيبقى الجهاز «نشطاً» حتى دقيقتين. إذا دخل شخص آخر أثناء نشاط الأول يظهر تنبيه في أعلى لوحة الإدارة (انظر التالي).
- **إعادة فحص قبل تشغيل الفيديو:** لا يصدر OTP من طلب فتح صفحة الدرس؛ يصدر من طلب POST مستقل بعد إعادة فحص الجلسة والحساب والجهاز. عند تغيير اعتماد الجهاز أو إيقاف الحساب تُبطل الجلسات، لكن لا يستطيع التطبيق سحب رمز VdoCipher سبق إصداره فوراً، لذلك يجب إبقاء مدة صلاحيته قصيرة.
- **تزامن الأجهزة:** تستخدم عملية تسجيل جهاز جديد وموافقة الأدمن قفل صف المستخدم في قواعد البيانات التي تدعم `SELECT ... FOR UPDATE` (مثل PostgreSQL) للحد من سباق اعتماد جهازين بالتزامن. SQLite المحلي لا يوفر القفل نفسه؛ يلزم اختبار التزامن على PostgreSQL قبل الإطلاق.
- **تنبيهات لوحة الإدارة:** عندما يظهر جهازان لنفس الحساب بنفس الوقت (دخول من جهاز ثانٍ أثناء نشاط الأول، أو محاولة من جهاز جديد أو غير معتمد) يظهر الحساب في لوحة «تنبيهات مشاركة الحساب» أعلى لوحة الإدارة مع أزرار: واتساب، إلغاء التفعيل، تجاهل. والصفحة المفتوحة تعرض شريط «تنبيه جديد» خلال 15 ثانية تقريباً. كما يظهر تنبيه عند وصول جهاز جديد بانتظار المراجعة أثناء فتح لوحة الإدارة. إلغاء التفعيل أو «تجاهل» يغلق تنبيه المشاركة، وإذا تكرر الوضع يظهر تنبيه جديد. التنبيهات تُحفظ في سجل الأحداث وتُعرض لآخر 7 أيام.
- **علامة مائية متحركة:** بريد الطالب ورقم واتساب يظهران فوق الفيديو (`WATERMARK_ENABLED=true`) عبر معامل `annotate` في طلب OTP لـ VdoCipher.
- **حدود معروفة:** الويب لا يستطيع إثبات هوية قطعة العتاد بشكل موثوق عبر المتصفحات. بصمة الشاشة ليست إثباتاً للجهاز، ومعرّف Cookie يعرّف تثبيت المتصفح/التطبيق لا الهاتف دائماً. إذا تغيّر المعرّف، فالمسار المقصود هو مراجعة الإدارة والتحقق عبر رقم واتساب المسجّل.
- الأجهزة المسجّلة قبل هذا التحديث تأخذ بصمتها تلقائياً مع أول نبضة (heartbeat) بعد الدخول. الطلاب المسجّلون حالياً سيُطلب منهم تسجيل الدخول مرة واحدة بعد النشر.

## الحسابات والأمان (تحديث)

- كلمات المرور الجديدة تقبل 12 إلى 128 محرفاً، وتُخزّن كـ hash باستخدام Werkzeug؛ كلمة المرور لا تُسجّل في سجل الأحداث.
- محاولات الدخول تُحدّ من عنوان الاتصال وبصمة بريد مشفّرة بـ SHA-256 خلال نافذة 15 دقيقة. تُحدّ محاولات التسجيل بخمس محاولات في الساعة لكل عنوان اتصال. هذه حدود تطبيقية وليست بديلاً عن WAF أو خدمة تحديد معدل على مستوى الاستضافة.
- حقل `email_verified` محفوظ للتوافق مع مخططات قواعد البيانات السابقة فقط؛ لا يرسل الموقع بريداً ولا يستخدم هذا الحقل للسماح بالدخول أو التفعيل.
- إعادة تعيين كلمة مرور الطالب تتم حصراً من الأدمن، ويتبعها إبطال جلسات الطالب السابقة. لا توجد روابط إعادة تعيين أو تأكيد بريد. يستطيع الطالب تغيير كلمة مروره بنفسه فقط إذا كان مسجّلاً ويعرف كلمة المرور الحالية.
- إيقاف حساب طالب أو جهازه يزيد `session_version` ويبطل الجلسات في الطلب التالي. يتطلب ذلك أن تكون `SECRET_KEY` ثابتة وسرية بين عمليات الخادم.
- على Render/Railway، يُستخدم `ProxyFix` لهوب واحد فقط لاستعادة عنوان العميل والبروتوكول من الوكيل الموثوق؛ لا تستخدم هذا الإعداد وراء سلسلة وكلاء مختلفة من دون مراجعتها.
- أضف `SUPPORT_WHATSAPP_NUMBER` حتى يظهر رابط الدعم للطالب. لا يحتاج المشروع إلى SMTP لإدارة الحسابات أو إعادة تعيين كلمات المرور.
